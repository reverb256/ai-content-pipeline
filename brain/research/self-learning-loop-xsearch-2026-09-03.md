Queries: "AI content pipeline continuous self-learning iteration loop" + "AI content factory quality improvement loop metrics playbook evolution 2026"

## The core pattern (Plan → Act → Observe → Reflect → Evolve)
Runs at THREE levels: individual content pieces, campaign batches, the meta-system.

1. PLAN: strategist sets goals from past performance + trends → brief with success criteria
2. GENERATE: variants at intensity levels (minimal/standard/full)
3. CRITIQUE (the maker-checker core): SEPARATE evaluator scores 1-10 per rubric dimension + names gaps; never generator-self-grade
4. REFINE: iterate until threshold (9/10) or plateau; keep full trajectory (Chain-of-Experience)
5. DEPLOY + MONITOR: real platform metrics
6. ANALYZE: combine behavioral + synthetic feedback; root-cause "this hook worked because..."
7. REFLECT/EVOLVE: update skill registry/memory with winning patterns; high-performers become few-shot/retrieval data; evolver proposes harness changes

## What maps to OUR system
- Generator≠Evaluator: gate_review.py + editor review = the Critic layer (need: confirm ALL stages covered)
- RULINGS.md + oracle-consumer = the skill-graph evolution (winning patterns → permanent rules)
- analyze.md report.json = the Measure layer (needs: real data — YouTube OAuth)
- oracle-watchlist = trend sensing
- MISSING: the cadenced Reflect→Evolve step — a weekly ritual that reads accumulated reports and converts lessons into playbook/RULINGS updates + metrics dashboard

## Metrics that matter (from search)
- Composite quality score (0-10 weighted rubric)
- Critique iteration count / rewrite-trigger rate (lower = maturing)
- Month-over-month quality delta
- Data coverage (% of pieces with full tracking)
- Post-publish: CTR, retention, dwell, conversion, revenue attribution
- System: autonomy horizon, improvement velocity, recovery speed

## Pitfalls named (we've hit these)
- Letting the generator self-grade (storyteller self-report — the maker-checker rule exists for this)
- Random non-data-driven prompt changes (need measured outcomes first)
- No data collection (the OAuth starvation)
- Ignoring underperformers (need the keep/test/stop loop actually fed)
