# Blog Platform Playbook

> The blog is the permanent library and the portfolio. Deep technical essays
> that index for years and prove both depth AND communication skill.

## Platform Rules

- 1-2 posts/week (deep essays, not quick hits)
- Astro + MDX (or the chosen stack), terminal-inspired aesthetic
- Every post: architecture diagram, concrete code/config, "what broke in
  production" section, "what I'd change for v2"
- SEO: title, meta, internal links, evergreen topics that answer specific
  searches
- RSS + newsletter signup
- The blog is the artifact — its repo, CI, and ops are themselves content

## Content Pillars (the permanent library)

1. Personal Knowledge / Systems as Platform Engineering
2. Developer Environment as Code (Omarchy, NixOS→Omarchy, dotfiles)
3. Personal Observability & Life Metrics
4. Automation & Orchestration (agents, kanban, cron)
5. Content Engineering Systems (the meta layer — this pipeline itself)
6. Portfolio Engineering (case studies of the systems we build)

## The Post Template

```markdown
# Title (outcome-led)

## The result (first screen, tangible)
## The problem (why this matters)
## The architecture (visible structure)
## The build (concrete code/config)
## What broke in production (the honest part)
## What I'd change for v2
## The takeaway (compressed, memorable)
```

## Interaction Mode

The blog is the one platform we fully own — it is a git repo + deploy target.
No browser needed.

## Metrics

- Search impressions / rankings (Search Console)
- Time on page, return visits
- RSS / newsletter subscribers
- Referrals to other platforms (the blog is the hub)
